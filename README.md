# 下諏訪 時間プランナー — Prototype

下諏訪町で「どこへ行くか」ではなく「どう時間を過ごすか」を提案するWebアプリの試作です。

## 現在できること

- Places CSVをブラウザから読み込む
- 座標登録済みPlaceを地図上に表示
- START / GOALを登録Place、GPS、地図クリックから設定
- 曜日・開始終了時刻・10時のおやつ・昼食・15時のおやつを指定
- 営業時間・定休日・「おやつ向き」「昼食向き」を使ってプラン候補を生成
- ランドマークを途中の＋αとして挿入
- 地図上でバス停・店舗・ランドマークを色分け
- トイレはPlace種別と分離した設備属性としてWCバッジ表示
- あざみ号・スワンバス統合GTFSを読み込み
- 徒歩のみ / 徒歩＋バス / バス優先（歩きを減らす）を選択
- START→徒歩→バス停→あざみ号/スワンバス→降車→徒歩→目的地を時刻表ベースで提案
- バス待ち時間、乗車時刻、降車時刻をタイムラインに表示
- 「別プラン」で飲食店・ランドマーク候補を変更

## 交通データ

`data/gtfs/` に、既存の `sususunosusumu/SHIMOSUWA-LAB` で作成した「あざみ号＋スワンバス統合GTFS v6」を同期しています。

使用する主なGTFSファイル:

- `stops.txt`
- `routes.txt`
- `trips.txt`
- `stop_times.txt`
- `calendar.txt`
- `calendar_dates.txt`

同期元:

`SHIMOSUWA-LAB/GTFS/shimosuwa_azami_swan_merged_gtfs_v6.zip`

`.github/workflows/sync-transit-gtfs.yml` がGTFSを取得・展開します。

## 移動方法

### 徒歩

現在は緯度経度間の直線距離に補正をかけて徒歩時間を概算しています。

### 徒歩＋バス（おすすめ）

徒歩のみと、近隣バス停から利用できるあざみ号・スワンバスを比較します。バスが大きく遠回りにならず、歩行量を減らせる場合はバスを提案します。

### バス優先（歩きを減らす）

多少時間が長くても、徒歩距離を減らせるバス候補を優先します。高齢者や長時間歩きたくない利用者を想定した試作です。

## 現在の制約

- 徒歩時間は道路ルートではなく直線距離＋補正の概算
- バス停まで/バス停からの徒歩も道路ネットワークではなく概算
- GTFSは静的時刻表で、リアルタイム遅延には未対応
- 画面では曜日を選択しているため、祝日・特定日の `calendar_dates.txt` 例外はまだ完全には反映していない
- バス乗継は現在「1本のバス＋徒歩」を中心に探索しており、複数回の乗換は未対応
- 一部Placesの座標・営業時間・属性は要確認
- イベントデータは未接続

## 第二弾：キーワードで行き先を探す

`discover.html`（下諏訪、なにしよう？）は、気分 → 詳しいキーワード → 地点詳細の順で探すページです。

- `place-data.js` の `loadAll()` を使い、時間プランナーと同じ149地点のデータとメンテナンス情報を読み込みます。データの複製は作りません。
- 「食べたい」「ひと息つきたい」「のんびりしたい」「まちを歩きたい」「見て・知りたい」「一杯飲みたい」「買い物したい」から深掘りします。
- 同じ気分の詳しいキーワードは複数選択でき、どれかに当てはまる候補を表示します。文字検索・雨の日・30分以内の条件は追加で絞り込みます。
- おすすめ順／近い順、下諏訪駅／現在地の距離基準に対応します。現在地は利用者がボタンを押したときだけ取得し、保存しません。距離は直線距離です。
- 「行きたい」リストはブラウザの `shimosuwa_discover_wanted_v1` に地点IDを保存し、候補をコピーできます。時間プランナーへのリンクはページ移動のみで、候補の自動取込は行いません。
- 地点詳細には公開項目のみを表示し、運営メモなどの内部項目は表示しません。

実装は `discover-model.js`（キーワードと絞り込み）、`discover-app.js`（画面操作）、`discover.css`（表示）に分かれています。

検証はリポジトリのルートで `node tests/discover-regression.cjs` と `node tests/discover-app-regression.cjs` を実行します。
